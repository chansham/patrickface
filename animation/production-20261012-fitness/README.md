## 製作與覆核流程

每套成功來源分開接入；只有原圖、輪廓、人體尺規和固定倍率都核對後，才進手動候選。舊候選與主日常素材不改。生成失敗、構圖不可用或還未核對的項目不算成品。

`manifest.json` 記各來源原圖SHA、原畫排列、獨立人體QC、全段固定倍率及已實看的問題。沒有成功PNG不建條目。`status: candidate-ready` 只表示可以進審稿頁，目錄仍是 `quality-revision-required`、`artApproved: false`。

逐套步驟：

1. 實看成功PNG，核透明與完整頭腳。用既有 `tools/build_frame_regions.py` 建輪廓；不改PNG、不硬裁方格。
2. 登記来源及原畫讀序，執行 `review_batch.py --id <候選ID> --images` 產黑／白底和輪廓圖，實看後記錄缺陷與落位方式。
3. 獨立人體量測可靠部分，遮擋／閉眼留未知。選整段固定倍率，確認所有版式安全區；不以手套、水瓶、毛巾等道具外框當人物大小。
4. 只有上述條件齊全才 `review_batch.py --id <候選ID> --integrate`。工具保護本輪開始前的26個候選；本批明確校準需版本遞增與完整舊候選快照，且source/regions不能偷偷替換。拳擊及外套由v1校準至v2，不增加候選數。
5. 現成 `preview/test-regions-browser.cjs` 以指定ID核對真RGBA、輪廓歸屬；本目錄 `capture_review.cjs` 測真1倍速、各格四版式與200px幾何，隔離儲存資料。每次只跑本次成功來源，避免把等待中的項目當通過。

`*-qc.json` 是輪廓與來源問題；`*-body-qc.json` 是人體尺規；`body-scale-audit.json` 供尺寸頁讀取。實際瀏覽器資料放 `output/playwright/fitness-20261012/`。技術檢查與藝術完成度分開記錄，不能以格數／套數表示動畫已完成。
